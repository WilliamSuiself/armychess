# 中国跳棋 × Jev / Laya

六角星 121 孔中国跳棋（Chinese Checkers），双人对角竞速，AI 座位接入
Jev / Laya 决策模型（与 blackjack / doudizhu / armychess 同一套
state+questions → answers 合同）。

## 玩法

- 红方（下方三角区）vs 蓝方（上方三角区），各 10 颗棋子。
- 每回合动一颗子：**单步**走到相邻空孔，或**连续跳跃**——跳过相邻棋子
  落到其正后方空孔，落地后可任意方向继续跳，随时可停。同一回合不可
  重复落脚，单步与跳跃不可混用。无吃子。
- 10 颗棋子全部进入对面三角区即胜。

## 运行

```bash
pip install -r requirements.txt
export KNOX_API_KEY=...      # Jev API key（或写入 .env）
python app.py                # http://127.0.0.1:5056
```

- `/` 对局页；`/replay` 回放页。
- 座位可选 玩家 / Jev / Laya（各标签页最多一个人类座位）。
- AI 2 秒决策超时 → 启发式兜底（净前进距离 + 优先送出起点棋子）。
- 回放 JSON 写入 `replays/`。

## 结构

| 文件 | 作用 |
|---|---|
| `rules.py` | 121 孔棋盘（轴向坐标）、走法/跳跃链 BFS、胜负 |
| `ai_engine.py` | build_state（规则+局势+剪枝候选）、questions、兜底启发式 |
| `app.py` | Flask + Match 线程循环 + 回放存储 |
| `jev_client.py` / `laya_client.py` | AI 后端（与其它棋类项目相同合同） |
| `static/` + `templates/` | 棋盘渲染（SVG）、跳跃动画、回放器 |

## 设计要点

候选走法按"净前进距离"剪枝（每颗子最多 2 条最佳跳跃链）得到一个较宽的
候选池，再跑 **2 层前瞻**重排：由于这是无吃子的竞速游戏，没有对手的
"惩罚性回手"要防，2 层前瞻改为衡量"这步棋是否为下一回合搭好了更大的
跳跃桥"——模拟走完这步后，计算我方任意一颗子在假想的下一回合能达到的
最大净前进，按一定权重加到这步棋的分数上，最终截断 14 个候选发给模型。
命中时候选标签会带 `🪜此后可再跳净进X` 标注；`move_fallback`（超时兜底）
同样用这个更深的分数。坐标为轴向 (q, r)，前端用 pointy-top 投影渲染。
对局页 AI 面板点"[查看完整请求]"可展开查看发给 Jev 的完整候选与标注。

**开局阶段**（前 14 个半回合）额外启用两条机制：state 中加入
`opening_guidance`，把双人跳棋公认的开局原则（深子先出——角尖子出路
最少，走中路——中心跳板最多且能堵对手快车道，前排子当跳板搭连跳链，
队形紧凑不孤军深入）明确告诉模型；同时本地打分加 `opening_score`——
出发区越深的子出走加分越高（深度 5~8 线性 +0.4~+1.6）、落点进中心六
边形加分、落在己方子旁边（保跳板）加分、深子未清时调动中场子小扣分。
符合原则的候选带 `📖开局` 标签，候选排序与超时兜底同样生效。

## 自进化：启发式权重的无人值守自我调优

`weights.py` 把 `opening_score`/`formation_score`/`two_ply_progress`/
`move_fallback` 里原本硬编码的系数抽成一份可调权重（`DEFAULT_WEIGHTS`），
`self_evolve.py` 用纯本地自对弈（不调用 Jev/Laya，零 API 成本）做进化式
调参：

1. 每代对当前冠军权重做高斯扰动生成若干候选
2. 每个候选与冠军对弈 N 局（颜色交替、小概率探索走法避免每局都完全
   相同），胜率达标（≥56%，带基本统计置信度要求）才有资格晋升
3. **回归门禁**：每隔几代用冠军权重对战"出厂默认权重"（冻结基线）
   复核一次，若低于及格线自动回滚——防止"连续打赢上一代祖先"但其实
   已经偏离整体更优方向的漂移
4. 每代、每次运行都落盘到 `evolution_history/`，带完整审计记录
   （晋升/未晋升原因、回滚事件、胜率数据）+ 一份 Markdown 汇总报告

只调数值系数、不碰任何逻辑代码——冠军权重文件 `weights_champion.json`
就是"模型"，`ai_engine.py` 运行时加载它，晋升新冠军后重启服务即可生效，
不需要改代码或重新部署。

```bash
python3 self_evolve.py --generations 10 --candidates 5 --games 24
```

生产环境部署为每晚定时任务见 `DEPLOY_EVOLVE.md`（systemd timer，限制
CPU 占比避免影响同机其它游戏服务）。
